## 二、六份设计机制的原样拆解

### 1. deepseek-harness —— 设计是「生态叙事」
- 品牌口号一句话可传播：「Everything is a Plugin」；topics 即发现机制（dsh-plugin）。
- 文档站（deepseek-harness.github.io）是唯一品牌面；README 极短——设计感来自**生态的秩序**而非视觉稿。
- 启示：壳类项目的「设计」是命名、话题、发现机制与文档站的一致性。

### 2. open-design —— DESIGN.md 品牌契约 + 校验脚本（最直接的范本）
- **151 个设计系统包**：`design-systems/<brand-slug>/` 下每包一份 `DESIGN.md`（可选 tokens.css / components.html）。
- **DESIGN.md 九节结构**（从 apple / airbnb 等既有系统归纳）：
  1. Visual Theme & Atmosphere（视觉主题与氛围）
  2. Color Palette & Roles（色板与角色）
  3. Typography（字体排印）
  4. Layout & Spacing（布局与间距）
  5. Components（组件）
  6. Motion & Interaction（动效与交互）
  7. Iconography & Imagery（图标与影像）
  8. Voice & Tone（语气与口吻）
  9. Edge Cases & Variations（边角与变化）
- 定位纪律：「DESIGN.md is a creative brief, not a schema」——先写氛围与意图，令牌是它的编译产物。
- **验证器 enforce 三条**：非空且含 H1；与参考系统的标题重叠 ≥30%；资产不得逃出品牌目录。验证脚本 `validate-design-system.sh` + 贡献技能 `od-contribute`（含 anatomy 参考与 PR 模板）。
- 证据文化：`.github/screenshots/` 收录触点实拍（hover-entry / hover-open / production-modal 五连拍）。

### 3. shadcn/ui —— 令牌三层 + 成对命名 + 派生尺（消费侧行业标准）
- 三层：**baseColor（primitive 基础色，7 种可选）→ semantic（语义令牌）→ 组件消费**。
- 命名纪律：表面与其上内容**成对**——`--primary` 与 `--primary-foreground`；场景成套——card / popover / muted / accent / destructive / ring / chart-1…chart-5 / sidebar-*。
- 派生尺：`--radius` 是唯一基准，`--radius-sm: calc(var(--radius) * 0.6)` 一路派生——改一个数，整把圆角尺跟着走。
- 色彩空间全面 OKLCH；暗色 = 同组令牌叠加 `.dark` 覆盖，边框用透明度语法 `oklch(1 0 0 / 10%)`。
- 消费方式：Tailwind `@theme inline` 把语义令牌映射为 `bg-background text-foreground`，改令牌不改组件。

### 4. opencode —— 主题即包 + 状态键（终端域最近类比）
- **34 个内置主题**，主题是 JSON 包：`base`（令牌树）+ `light` / `dark`（各一套 hue 色相盘）。
- 色相 9 阶（100–900，方向随模式对比度翻转）+ alias（accent / interactive / neutral）——「覆盖一个 alias 就改一族相关色」。
- token 组按职责分：text / background / border / scrollbar / **diff** / **syntax** / **markdown**；raised 表面三层（base/high/max）；**@dialog 上下文表面**（对话框内重新解析调色板）。
- **状态键**：`$hovered / $focused / $pressed / $selected / $disabled` 直接写进主题文件，未指定则回退 base——交互态是主题的一等公民。
- 每主题自带语法高亮与 Markdown 元素全套配色（9 个 syntax 键 + 13 个 markdown 键）。

### 5. archify —— 机器可读验收证据链（此前已解剖，此处归档结论）
- candidate.json（规范，含 sha256）→ delivery.json → browser-check.json（真实浏览器逐视口溢出检查）→ finalize-summary（gates 全 pass）。
- containment 策略字段：图超出视口怎么办，是声明出来的预案而非事后补丁。

### 6. impeccable —— 确定性检测 + 设计钩子（此前已解剖，归档结论）
- 62 条零大模型规则挂在 Agent 文件改动循环上，保存即拦；PRODUCT.md / DESIGN.md 双契约文件；24 个动词把「好看一点」拆成动作。

## 三、「看着就像那么回事」的七个来源（差距的真正拆解）

1. **DESIGN.md 是品牌契约，不是令牌注释**。九节结构从氛围到边角变化；令牌只是第 2、4 节的编译产物。→ PWORK 的 DESIGN.md（70 行）只有令牌表与纪律，**九节缺六节**（氛围、组件、动效、图标影像、语气、边角）。
2. **令牌三层 + 成对命名 + 派生尺**。→ PWORK 的 tokens.css 是单层语义表：无 primitive 层、无 bg/fg 成对、圆角无派生尺（三档手写）、色值 HEX 直写未入统一色彩空间。
3. **主题即包，交互态是一等公民**。→ PWORK 只有 `:root` 加暗色覆盖（且暗色塌过一轮，复盘 7.2）；无状态键、无 raised 表面分层、无上下文表面。
4. **机器可读验收**。→ PWORK 无设计验证脚本：对比度靠人查（tokens 注释里的 4.57/5.14 是手算的）、无结构校验、无浏览器实测回执。
5. **文档站即品牌面**。→ PWORK 的 /design 页是「应用内实时样例」（这一点比多数开源项目强），但没有对外品牌面：无截图档案、无同需求对比图、无 changelog 叙事。
6. **真实资产与真实对比**。→ 高星项目的 README 首屏全是真截图 / live artifact；PWORK 的物料以手绘示意为主。
7. **Voice & Tone 成文**。→ PWORK 有「说人话」纪律，但没成节、没有正反例句库。

## 四、PWORK 已有的、不必自卑的部分

- 唯一强调色纪律 + 类别色只作边线与标签——比多数高星项目克制得更彻底；
- 字号 8 级阶梯 + `calc(13px * var(--font-scale,1))` 偏好缩放——用户偏好不改令牌结构，这个思路 opencode 用 alias 实现，PWORK 用 calc 实现，同级；
- 对比度预算制（每个改值注明实测对比数）——shadcn 也没做到这个程度；
- /design 实时样例页——文档与实现同源的活证据。

## 五、补齐路线图（按投入产出排序）

**阶段一 · DESIGN.md 升格为品牌契约（一天量级，纯写作）**
把 70 行令牌表扩成九节契约，素材全在现有资产里：氛围节（「冷静的工作台」三条纪律展开 + 反面清单）、动效节（150–300ms 四档 + reduced-motion 总闸成文）、语气节（「说人话」配正反例句）、边角节（空态/报错/超长/离线清单，素材来自复盘 3.58）。写完跑一次结构自检（对照九节重叠 ≥30%）。

**阶段二 · 令牌三层化 + 主题包化（两三天量级，动 tokens.css）**
- 加 primitive 层：色值原值沉底，语义层引用（`--amber-500: #e8833a; --accent: var(--amber-500)`）；
- 成对命名：`--accent-foreground`、`--surface-foreground` 等配对补齐；
- `--radius` 派生尺：三档圆角改 calc 派生；
- 主题包化：暗色抽成独立主题文件，补状态键（hovered/pressed/disabled）与 raised 表面分层；
- 写 `scripts/validate-design-system.sh`：对比度全表自动计算（AA/AAA 分级输出）+ 九节结构重叠检查 + 令牌覆盖率（页面用色值字面量 vs 令牌引用的差集）。

**阶段三 · 对外品牌面（持续）**
- README 首屏换真实截图档案（建 `.github/screenshots/`，每个模块一组实拍）；
- 同需求对比图：同一页面的「设计系统前后」各一张；
- /design 页升级为对外可访问的品牌面；
- 参照生态登记法（topics / 姊妹项目互引）进入 Harness 生态的发现机制。
