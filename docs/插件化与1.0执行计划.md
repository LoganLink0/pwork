# 插件化与 1.0 执行计划（子代理验收标准）

> 2026-11-10 用户拍板三段走：**功能补完 → 架构优化 → 1.0 视觉大版本（含小 P 吉祥物形象）**。
> 本文件是后续每批工作的执行方案与验收标准：每批开工前读对应小节与通用验收标准，收尾逐条核对。
> 排队纪律、回归清单、协作规则以 AGENTS.md 与 development.md 为准，本文件只加不改。
> 产品定位：PWORK 是父目录下各项目（RESUME/MIND/MetaVault/FEYNMAN/COOKMASTER/HEAL 等）的**中枢**——
> 本项目定义接口（数据进出、工具调用），其他项目按接口改造配合本项目；交互走进程外组合（HTTP/文件/命令行），
> 明确不做运行时加载外部代码（供应链面不可放开）。

## 通用验收标准（每一批都必须全过，缺一即退回）

1. **最终树全量重跑三项**：vitest 全绿（基线 565 起，只增不减）、`tsc -b` 0 错误、lint 警告数不超过基线（5 条）。引用「之前跑过」的结果无效——类型检查与测试每批都在最终树上全量重跑（复盘 3.69）。
2. **真实走查**：功能批必须有 `local/verify-*.py` 无头走查脚本，走用户真实路径（隔离 profile 造数、测完清场）；纯代码扫描与单测通过不构成验收（复盘 3.68）。
3. **数据安全批附加**：不碰用户真实库；镜像（vault）与备份（导出/导入/自动备份）口径同步核对；启动数据检查的基准不因本批误触发。
4. **界面与文案**：说人话检查表（内部词 grep 命中即改，不自造词）+ 入口三问（三步可达/空态有指引/同一概念全站同名）。
5. **收尾留档**：TODO 留档带提交号；提交信息不含文件路径字样；GitHub + Gitee 双推；零个人信息 grep（IP/绝对路径/账号名）。
6. **平台附加**：涉桌面行为（Rust/网关/文件系统）→ `npx tauri build` + 装机冒烟；涉发版 → 发版同步清单逐项勾。
7. **断言查证**：对外部服务/依赖的能力断言先查官方文档具体页面；否定性结论需要更强证据（复盘 3.21/3.33）。

**子代理标准执行序列**：AGENTS → 交接文档 → TODO 当前队列 → 本文件对应小节 → 开发复盘对应教训条 → 实施 → 通用验收 1–7 → TODO 留档 → 提交双推。

## 阶段一：功能补完

### 1.1 条目版本回退（R7）

- **目标**：条目正文被误改后可一键回到上一版。
- **方案**：条目保存前把旧的标题/正文存进条目自身的 `prev` 字段（只存一份，不建版本链）；阅读视图与条目编辑入口提供「恢复上一版」；恢复动作本身也先把当前版存进 `prev`（可来回切）。
- **验收**：①编辑→恢复→再恢复来回切换，标题/正文/标签数据无损；②`prev` 随备份导出/导入、vault 镜像往返一致；③正文检索只搜当前正文，`prev` 不进命中范围；④存量无 `prev` 字段的条目全部兼容（读取防御）；⑤测试覆盖往返与恢复边界。
- **风险**：①条目体积接近翻倍（大正文）——只存一份可控；镜像文件格式加段需同步 obsidian 导出格式说明；②导入旧备份缺字段——normalizeItem 补默认；③「恢复上一版」按钮的误触后果是覆盖当前版，需确认弹层（危险动作红键）。

### 1.2 保存的过滤器（R8）

- **目标**：条目库/待办的筛选状态可命名保存、一键套用。
- **方案**：筛选状态序列化存 kv（每库一套，带 schema 版本号），条目库工具条加「保存当前筛选/我的过滤器」；命令面板列出已存过滤器；URL 参数可携带（与 focus 参数同机制）。
- **验收**：①保存→切换其他筛选→套用回来状态完全一致；②刷新与重启后过滤器仍在；③命令面板可直达；④坏数据（手改 kv）回落空态不崩。
- **风险**：筛选字段随功能演进漂移——序列化带版本号，未知字段忽略；与按月分页的交互（过滤器含月份时以过滤器为准）。

### 1.3 播客信源（R11）

- **目标**：播客 RSS 能进信源体系，条目标出「含音频」与时长；只做发现与记录，不做播放器。
- **方案**：抓取解析时识别 enclosure 音频附件 → 条目记 `hasAudio` + 时长；信源页类型徽章「播客」；朗读页不消费此类条目。
- **验收**：①真实播客 feed（至少 3 个不同托管商）抓取入库、徽章与时长正确；②普通 RSS 不受影响（回归）；③单测覆盖 enclosure 解析纯函数。
- **风险**：①播客 feed 体积大（单 feed 常数百条目）——现有 4MB 抓取上限实测核一遍，不够则对该类型放宽并说明；②enclosure MIME 各家不一（audio/mpeg、mp4、甚至缺 MIME）——按扩展名与 MIME 双判；③时长字段有的 feed 没有——缺省留空不编造。

### 1.4 关键词监控表单（R12）

- **目标**：添加信源时输入关键词即可生成监控地址，零引擎改动。
- **方案**：添加信源表单加类型「关键词监控」：输入关键词 → 生成 RSSHub 公共实例路由预填 URL（**默认走 RSSHub 公共实例，不默认 Google News——大陆直连不可达**）；关键词 URL 编码；生成的信源与普通 RSS 同管线。
- **验收**：①输入中文/英文/含空格关键词生成可抓取的信源，真实抓取入库；②特殊字符（`#`/`&`/引号）编码正确；③查证 RSSHub 关键词路由的官方文档后再定模板（断言查证纪律）。
- **风险**：①公共 RSSHub 实例限流/不稳——已有转接回落机制兜底；②关键词类信源的条目质量靠现有投票闭环消化，不加新参数。

### 1.5 循环待办与习惯追踪（R13 + backlog 22，合并批）

- **目标**：周期性事项自动派生下一期；任务有完成记录，复盘多一层行为数据。
- **方案**：任务加可选字段 `recurrenceDays` 与完成记录（只保留近 52 次）；任务闭环时**从完成日**派生下一期到期日（防逾期雪崩）；编辑器加「重复间隔」下拉；复盘页任务区补完成热力条。移动端同构。
- **验收**：①派生边界测试全过（完成日=今天/跨月/跨年/闰日）；②旧任务无新字段完全兼容；③备份导出/导入、设备同步、vault 镜像四处口径一致；④热力条与用时口径不引入新的开发者词汇。
- **风险**：①任务模型变更牵动面大（备份/同步/镜像/报告统计四处消费）——normalizeTask 补默认 + 逐处核对；②日期一律本地日口径（项目有过 UTC/本地口径教训）；③完成记录截断策略写明（近 52 次），避免无限增长。
- **量级**：本阶段最大的一批，单独占一个完整批次。

### 1.6 移动端数据通路首验（收尾）

- **目标**：手机 PWA 两步配对 + 设备同步互拉互推真实验证。
- **方案**：手机端点填 `https://pwork-api.loganlink0.cn` → 扫码配对 → 互拉互推；写路径细节按首验结果定。
- **风险**：iOS Safari 存储回收（WKWebView 耐久性，观察项已有）；发现的问题按「记录级增量同步」既有体系修，不另起炉灶。

## 阶段二：架构优化（插件化地基）

### 2.1 本地库读写接口 + MCP（R4 提级进本阶段，先做）

- **目标**：外部程序（其他项目、外部 AI 客户端）能在授权下读写 PWORK 的速记/任务等核心数据。
- **方案**：分两步。①**库读写 HTTP 接口**：本地网关新增 `/api/library/*` 端点——列出/追加速记、创建/更新任务、打标签；鉴权沿用网关既有三道闸 + 新 Token；**第一版只开放「只增」操作（速记追加、任务创建），不开放改/删**；全部写操作走网关单点进存储层（多进程不直连库文件，SQLite 单写者原则）。②**MCP 薄壳**：独立小进程以 stdio 提供 MCP 协议，工具集即 ① 的接口子集；协议按官方规范实现（动手前查 modelcontextprotocol.io 具体页面）。
- **验收**：①无 Token 请求被拒；②真实 MCP 客户端连上 → 列出工具 → 追加速记 → PWORK 界面可见该条；③接口对表名/字段白名单校验（注入串直接拒）；④PWORK 未运行时 MCP 如实报错不挂起；⑤官方 MCP 校验工具（inspector）过一遍。
- **风险**：①写接口滥用面——只增白名单 + Token + 速率上限三层压制；②MCP 协议版本演进快——锁一个稳定版本号实现，不追最新；③网关挂掉时外部客户端的失败要人话可读；④此批引入的新目录（`mcp/`）在 2.2 模块目录化时按模块归位。

### 2.2 模块目录化

- **目标**：模块边界从目录约定变成物理隔离，为「插件 = 一个目录」铺路；视觉大版本前必须完成（否则全站改样式影响面数不清）。
- **方案**：把输入/处理/输出逐个迁成 `modules/<name>/` 自包含形态（页面/组件/引擎随模块走）；**跨模块共享层不动**（db 存储层、shell 组件、registry 注册表、网关客户端）；回路模块已是此形态，作为参照。一次只迁一个模块，独立提交，每步全量回归。配置统一 path 别名减少相对路径。
- **验收**：①每步迁完 565 全绿 + tsc 0 + lint 持平；②构建产物 chunk 数量与体积迁移前后对照（懒加载不退化）；③全路由走查一遍（26+ 路由健康）；④contracts.test 扩展断言「模块目录完备性」。
- **风险**：①搬移会暴露隐藏耦合（循环 import）——暴露即解决，不留 `// 临时` 豁免；②量大且机械——禁止与功能批混做，避免合并冲突面失控；③vite 别名配置一次成型（改 vite.config 有一次编辑成型纪律）。

### 2.3 动作注册表

- **目标**：命令面板、工具轮盘、全局快捷键、通知回执四处动作同源。
- **方案**：新建动作注册表 `{ id, 名称, 图标, 可用入口, 执行函数 }`，四个消费方改读注册表；轮盘格位配置映射到动作 id（旧配置迁移函数一次性转换）。
- **验收**：①契约测试断言动作清单完备（面板出现的动作必有执行函数与中文名）；②面板/轮盘/快捷键三入口实测同名动作行为一致；③旧轮盘配置迁移后行为不变（回归测试锁住）。
- **风险**：轮盘配置兼容迁移出错会破坏既有用户配置——迁移函数带测试，坏配置回落默认并提示。

### 2.4 外部工具传参调用

- **目标**：工具箱的「外部工具」从纯跳转升级为带上下文的调用（把选中文本/条目 id 传给外部程序）。
- **方案**：外部工具配置支持 URL 模板与命令行模板，占位符 `{selected}` `{noteId}` `{itemId}`；桌面版命令行以 argv 数组逐参传递（**绝不拼 shell 字符串**）；URL 仅 http/https。
- **验收**：①占位符替换正确（含引号/换行等特殊字符的选中文本）；②命令行注入测试：参数含 `&`/`|`/`"` 时不被执行；③无选中上下文时占位符置空不报错。
- **风险**：命令行模板是新增攻击面——argv 数组 + 无 shell 是硬边界，测试锁死。

### 2.5 外部项目接入试点（RESUME 先行）

- **目标**：验证 2.1–2.4 的接口在真实项目上跑通，沉淀接入文档。
- **方案**：RESUME（简历辅导工作台，浏览器 UI + 本地 Node sidecar）试点：诊断会话结束 → 调 PWORK 库接口写一条速记/复盘记录；PWORK 工具箱注册 RESUME 为带参调用。其他项目按需复制此模式。接入文档 `docs/外部项目接入.md`（三步：暴露入口/写回数据/注册工具）。
- **验收**：①RESUME 侧真实跑一轮诊断，PWORK 速记出现对应记录，字段完整；②PWORK 侧无感知（不改内部代码即被外部写入）；③接入文档按三步可照做。
- **风险**：①跨仓库工作边界——每个项目独立提交独立推送，PWORK 仓库只进接口与文档；②接口兼容——路径带版本号（`/api/v1/`），后续演进不破坏已接入项目；③RESUME 的 sidecar 与 PWORK 网关端口冲突——约定端口段，接入文档写明。

### 2.6 契约测试补全

- **目标**：插件化的持续保障——结构漂移在 CI 就被拦下。
- **方案**：三张断言表入 contracts.test：模块目录清单、动作注册表清单、网关库接口端点清单；CI（tests.yml）已跑 vitest，自动生效。
- **验收**：故意删一条注册触发 CI 红；修复后恢复绿。

## 阶段三：1.0 视觉大版本（暂定 1.0 的核心内容）

### 3.1 品牌吉祥物（小 P 玩偶形象）

- **目标**：给「小 P」（P = Perfect Partner 完美搭档）一个有身体、有性格的玩偶/吉祥物形象——它是发布页三段故事（一只耳朵：它先听；一只伸出的手：整理好递给你；Partner：只属于你的伙伴）的化身。对标研究已完成：**[09-品牌形象对标研究.md](./design/09-品牌形象对标研究.md)**（七个案例：WorkBuddy/Miora 为直接同类——腾讯 AI 办公工作台、角色即 Logo 趋势；Duolingo Duo、知乎刘看山、GitHub Octocat、Rust Ferris、Go Gopher、熊本熊），设计决策八条（人设一句话/形态同源/核心特征清单/表情集对齐用户旅程/触点克制红线/权利分层/交付物清单/流程）在该文档第二节。
- **方案**：①**角色设定稿先行**（照对标研究的决策 1–3）：性格关键词、形态规则（与 P 字标同源的圆/耳朵/手）、色值锁定 tokens.css 记录对（#e8833a / #b0500f）——写成可执行的一页规范，而不是每次重画；②AI 生成候选多版本（版本化纪律：v1/v2 存档 `docs/assets/mascot/`），用户拍板定稿；③定稿矢量化（SVG）保证全站任意缩放；④应用内落点：问小 P 圆钮升级为形象（默认/思考中/回答完成三态）、空态与引导页出现、错误页安慰态；⑤物料：应用图标、启动屏、介绍页 hero、发布页故事卡换真形象。
- **验收**：①角色规范一页（三视图/色值/使用场景/禁止用法）入仓（追加为对标研究文档的终稿章节）；②应用内至少四个落点实拍核对（形象三态渲染、缩放不糊、暗色适配）；③与现有 P 字标同源可辨识；④物料套图重出并按版本归档；⑤核心特征清单逐落点核对（耳朵/圆手/比例/色对四项缺一即返工——对标案例的一致性教训）。
- **风险**：①AI 生成跨姿态一致性差——靠规范稿约束特征清单（耳朵形状/比例/色值）而非重新生成；②形象与现有 IP 撞车——定稿前做相似度自查；③可爱感与工具感失衡（效率工具不做成玩具）——落点克制：只在伙伴性场景出现（问小 P/空态/引导），数据与设置类界面不出现；④启动屏与图标的系统侧缓存——发版清单 J 区元数据自查段覆盖；⑤权利归属写明（生成方式与授权分层，对标 Go Gopher 署名惯例与 Ferris 宽松授权先例）。

### 3.2 视觉体系改版

- **目标**：以吉祥物为中枢的整套视觉语言升级（色板/圆角/阴影/动效/组件形态）。
- **方案**：①tokens.css 层重做，DesignSystem 页（/design）作为对照基线——新样式先全量落在该页，走查认可后按模块逐个替换（依托 2.2 的模块边界）；②暗色同步、移动端同构、AA 对比度红线不破；③借机拆分巨型样式文件（base/组件/模块三段）。
- **验收**：①全路由截图新旧对照存档；②走查十五维清单全过；③窄屏（390px）与暗色巡检零残留；④物料与介绍页全量重出（版本化归档）进发版清单。
- **风险**：①全站回归面大——逐模块替换、每模块独立提交；②历史样式文件牵一发动全身——拆分与改版分两步，不混做；③用户验收节奏——每模块出预览对照，拍板后再进下一个。

### 3.3 1.0 定版

- **方案**：定版门槛五条核对（05-路线图）+ 三十天稳定窗口结论 + 发版同步清单全项 + macOS 真机验证 + 手机窄屏验收 + 遗留用户动作清零（Discussions Pin 等）。
- **风险**：窗口期发现的问题回流阶段一/二清单，不为赶定版压缩验证。

## 跨阶段风险与红线

1. **接口是承诺**：2.1/2.4 的接口一旦有外部项目接入，变更就是破坏性操作——版本号 + 弃用周期双保险。
2. **架构批不夹带功能**：2.2/2.3 期间发现的新功能想法一律入 backlog，不进当前批。
3. **数据口径不动摇**：所有批次的备份/镜像/同步口径变化必须三处同步核对并留测试（铁律）。
4. **规模 ×10 检查**：每批方案问一句「数据/频率/用户规模 ×10 后还成立吗」——模块目录化让新增成本线性、接口白名单让滥用面有界，均通过。
5. **本文件是活文档**：每批收尾把实际偏差（方案改动/新风险）回写对应小节，禁止留过时方案给下一批子代理。
