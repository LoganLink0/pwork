# 竞品对标 TOP3 · 商业市场三路线（2026-11-13）

> 与 [竞品对比评估-2026-11.md](./竞品对比评估-2026-11.md)（开源同类四品类）互补：本报告对标**商业市场三路线的代表**——
> 云端全能工作台（Notion）、本地优先知识库（Obsidian）、AI 原生笔记（Tana）。选型理由：三条路线的用户基数、
> 产品成熟度与 2025 年动向足以代表同类软件的最高水位；PWORK 的立场（本地优先）与形态（四模块闭环+伙伴 AI）
> 与三家各有正交的对照面。信息截至 2026-11-13，来源见文末。

## 一、TOP3 选型理由

| 路线 | 代表 | 为什么是它 |
|---|---|---|
| 云端全能工作台 | **Notion**（3.0） | 赛道定义者；AI 功能最激进的产品化样本（自定义 Agent / 数据库自动化 / AI 连接器） |
| 本地优先知识库 | **Obsidian**（1.10/1.11） | 本地优先立场的最大代表（与 PWORK 同立场）；插件生态与数据主权实践的对标核心；Bases 数据库视图是新方向 |
| AI 原生笔记 | **Tana** | Supertag 结构化 + AI Agents（读笔记实时行动）的代表；2025 年产品漂移（转向 agentic 会议平台）本身是重要警示样本 |

## 二、逐家深拆（2025 年底状态）

### 2.1 Notion 3.0 —— 代理执行 + 数据库自动化

**2025 年动向**：3.0 发布**自定义 AI Agents**（自主执行 20+ 分钟的跨页面复杂工作，拥有独立计算环境与浏览器）；数据库行级权限；AI 连接器扩容（Slack / Google Drive / GitHub 等）；数据库自动化（触发-动作规则：变更→通知/编辑页面/Webhook）；AI 数据库属性（每行自动生成摘要/翻译/关键词）。安全侧引入 **"Review for me"** 模式（Agent 产出需用户复核）。

**对 PWORK 的启示**：
- **差距（真实）**：问小 P 当前是"问答+检索"级；Notion 已到"代理执行"级（多步骤、跨页面、长时间自主工作）
- **哲学巧合**：Notion 的 Review-for-me 与 PWORK 的"伙伴递铲子不替你挖"（backlog 32 主动整理建议）是**同一安全哲学**——确认权在用户
- **可直接借鉴（轻）**：条目级 AI 摘要属性（每条日报/速记自动一句话摘要，进列表显示）——见清单 41
- **立场性不做**：AI 连接器（拉 Slack/网盘进 AI 上下文）与多云协作——违背"数据不外传、伙伴只属于你"，且与设备同步（自有 D1）路线重复

### 2.2 Obsidian 1.10/1.11 —— Bases 进核心 + 剪藏深化

**2025 年动向**：**Bases**（数据库视图）从插件转核心——查询/公式/卡片视图/嵌入式视图；官方 **Web Clipper** 持续强化（模板逻辑：条件/循环/回退在路线图）；社区主流工作流已是 Clipper+Bases 构建"剪藏→可查询档案"管线；路线图上有 **headless 同步**（不开主程序也能同步）。

**对 PWORK 的启示**：
- **差距（真实）**：PWORK 没有浏览器剪藏入口（网页捕获是构想池 30 划词捕获的轻量版）；条目库的"保存的过滤器"（0.1.18）与 Bases 的查询视图相比缺**卡片视图与嵌入视图**（把查询结果嵌进任意页面）
- **可直接借鉴（轻）**：把保存的过滤器升级为**可嵌入的保存视图**（首页可嵌"本周待办视图"、日报页嵌"未读条目视图"）——见清单 42
- **同构验证**：Obsidian 的 Web Clipper+Bases 管线 = PWORK 的条目抓取+保存过滤器+AI 评分——**同一需求的两种实现**，PWORK 的差异在读后回路（评分→投票→成稿→复盘，Obsidian 无此段）
- **headless 同步的启示**：PWORK 的云端采集（worker 7×24）本质就是 headless 数据通路——已具备，无需跟进

### 2.3 Tana —— Supertag/AI Agents + 产品漂移警示

**2025 年动向**：AI Agents（实时读笔记并行动，类嵌入式 CustomGPT）；2025 年下半年**产品漂移**——推出独立的 agentic 会议平台（AI 在视频会议中实时干活），社区对"新 Tana"反应 mixed。

**对 PWORK 的启示**：
- **警示样本（重要）**：Tana 追逐 agent 热点转向会议赛道，核心笔记产品被稀释、社区反应分化——**PWORK 的 Perfect Partner 必须钉在"个人工作台"本位**，伙伴能力（胶囊岛/问答/整理建议）都是为四模块服务的，不为 agent 而 agent
- **Supertag 的对照**：PWORK 的对应物是**类别标记+模块语义**（3px 边线/标签，克制不做结构化模板）——立场性差异，不跟进
- **可借鉴（中）**：AI Agents "实时读你的数据并行动"的体验形态——PWORK 的对应路径是 **MCP 读接口**（backlog 38 已入档）+ 主动整理建议（32），保持用户确认权

## 三、四维横向对比

| 维度 | Notion 3.0 | Obsidian 1.11 | Tana | PWORK 0.1.22 |
|---|---|---|---|---|
| 数据主权 | 云端（可自托管企业版） | 本地文件+付费同步 | 云端 | **本地 SQLite+自部署 D1** ✓ |
| AI 形态 | 自定义 Agent（自主执行） | 插件生态承担 | AI Agents+会议转向 | 问小 P 问答+检索（ agent 化是差距） |
| 捕获广度 | 网页/连接器/导入 | Web Clipper+插件 | API/快捕获 | 三级抓取+导入+剪贴板+MCP 写 ✓（缺浏览器剪藏） |
| 组织范式 | 数据库+页面 | 文件+链接+Bases 视图 | Supertag 结构化 | 四模块+类别标记+保存过滤器 |
| 读后回路 | 无（数据库自动化止于通知） | 无 | 无 | **评分→投票→成稿→复盘闭环** ✓ 独有 |
| 移动端 | 原生全平台 | 原生全平台 | 原生 | PWA（数据通路受限）——已知差距 |
| 隐私/遥测 | 云端遥测 | 本地+可选同步 | 云端 | **零遥测零账号** ✓ |

**诚实结论**：PWORK 的独有价值在**读后回路闭环 + 本地主权 + 伙伴人格**；全面差距在 **AI 代理化程度、浏览器剪藏、原生移动端、生态规模**。前两项有明确可做的清单（见五），后两项受立场与资源约束（移动端在首验路线上、生态随开源自然生长）。

## 四、三家共同趋势与 PWORK 的站位

**2025 年三家全部压注 AI 代理**（Notion agents / Tana agents / Obsidian 靠插件生态间接承担）——行业共识是"AI 从问答走向执行"。PWORK 的差异化站位：**执行发生在用户本地、确认权在用户、呈现位是胶囊岛**——这条路线与三家（全部云端执行）正交，是本地优先立场下的独特位置。

Notion 的 "Review for me" 与 PWORK 的"伙伴递铲子不替你挖"哲学同源——**安全确认权是 agent 时代的产品护城河**，不是负担。

## 五、能做的清单

### 5.1 与既有 backlog 的关系（引用不重复）

- 网页划词/剪藏 → 构想池 **30**（轻量划词版已入档；本报告升级为完整剪藏扩展，见 5.2 新条 40）
- 主动整理建议 / Review 哲学 → 构想池 **32**（已入档）
- MCP 读接口（外部 AI 读 PWORK）→ 构想池 **38**（已入档）
- 保存的过滤器深化 → backlog **15**（已完成 0.1.18；视图化升级见 5.2 新条 42）
- 用户自定义自动化（Notion database automations 的对应物）→ backlog **16**（已入档）

### 5.2 新增条目（入 backlog，编号续 40 起）

**40. 浏览器剪藏扩展（对标 Obsidian Web Clipper；触发：构想池 30 划词捕获验证需求后升级）**
完整形态：整页正文剪藏（复用条目抓取管线）/ 选区剪藏（带出处）/ 模板化字段（标题/标签预填）。轻量起步可先做"书签脚本+本地网关写入接口"（0.1.18 的 MCP 写接口即后端，零新后端）。

**41. 条目 AI 摘要属性（对标 Notion AI properties；触发：AI Key 配置率与成本核算通过）**
每条日报/速记一条 AI 一句话摘要存为字段，列表与胶囊岛显示——"已经替你读好了"的实体化。成本护栏：仅用户配置 Key 时启用、批处理限速。

**42. 保存视图与嵌入视图（对标 Obsidian Bases；触发：保存的过滤器使用率数据支持）**
保存的过滤器（已有）升级为可命名视图+卡片形态+可嵌入任意页（首页嵌"今日待办视图"、日报页嵌"未读视图"）。

**43. AI 代理执行的轻量路径（对标 Notion 3.0；立场护栏：确认权在用户）**
问小 P 从"答"走向"做"的渐进：批量归类建议（backlog 32）→ 定时简报生成（构想池 34 周报故事线）→ 多步任务链（"整理本周速记并生成周报草稿"）——每步执行前预览、执行后可撤销；呈现位=胶囊岛活动态。触发：1.0 后 agent 需求真实出现。

**44. 全屏避让与专注模式（对标所有悬浮件的让路原则；随胶囊岛批次顺带）**
全屏应用/演示时胶囊岛自动下沉或隐藏（Win32 前台窗口全屏检测），偏好开关。

### 5.3 立场性不做（本报告明确排除）

- AI 连接器拉外部服务进 AI 上下文（违背数据不外传）
- 协作/多人/会议方向（Tana 漂移的警示；单人本位）
- 结构化模板强约束（Supertag 式分类学——PWORK 的克制标记是立场选择）
