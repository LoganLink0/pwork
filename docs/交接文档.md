## 用户明确的纪律（违反=返工；持续追加）

1. 出错立即暴露 + 错误日志留痕——`void asyncFn()` 要想过"它拒绝了谁知道"。
2. 界面与文档说人话，禁自造词/编号黑话。
3. 分发产物零个人配置。
4. 写库前后对账；测试/演练永不碰真实库。
5. 改完必须 curl 验证 served 内容（Vite watcher 竞态，最高频坑）。
6. 追问优先：需求不清先问产出给谁/输入是什么/完成标准。
7. **严禁"现成件冒充原理推演"（AGENTS 设计规则 3a，三问判定）**——一周内五案例留档复盘 3.20。
8. **断言先查证：否定性结论需要更强证据；给用户的操作指引本身就是断言，写之前必须查官方文档或自证（复盘 3.33 是 3.21 同型再犯）**；用户确认的错由 AI 修到底，不推给用户手动改。
9. **所有待做任务必须写进 TODO.md**，不许只留在会话或口头。
10. **第一性原理优先（2026-10-28 用户明令）**：如果有更好的做法，要直接指出来，说明收益、约束与限制；不允许只基于原有代码缝缝补补。方案比较时先回到"假如现有组件全不存在，这个需求我会怎么设计"（AGENTS 设计规则 3a 三问的日常应用），再决定是重构还是增量。
11. **产出物版本化纪律（2026-10-28 用户明令）**：图片等对外交付物凡做修改，必须按版本号递增另存为新文件（如 promo-1080-v2 → -v3），禁止原地覆盖——旧版可回溯、改动可比对、引用方可指名（复盘 3.38 的资产存档纪律升格为强制）。

## 环境注意（Windows 重灾区，详见复盘第三节）

- 杀进程前先 netstat 查身份：5177/5180/5274/5275 是用户其他项目（Corealize/MIND/RESUME），不是本项目的；本项目杀 5273/8788 前先确认 PID 归属。
- Git Bash 的 curl 发中文是 GBK——测网关中文请求用 `--data-binary @utf8文件`（复盘 3.16）。
- **改 vite.config.ts 必须一次编辑成型**——watcher 读到中间态会崩 dev server（复盘 3.19 第三坑）；vitest 环境已守卫不会误拉网关。
- **子进程用 fork + stdio:'ignore'**：从 vite 进程 spawn 继承控制台在 Windows 下 0xC0000142（复盘 3.19 第一坑）。
- IAB 浏览器 evaluate 在隔离世界；locator.click 卡可操作性时用 `locator.evaluate(el => el.click())` 兜底（复盘 2.8）。IAB 的 localStorage/IndexedDB 是独立测试档案，别当用户真实数据。
- 源文件一律用编辑工具写（Mimosa 钩子拦 Bash 写源码）；提交信息里出现文件名字样可能误触发钩子，拆开跑即可。
- **FS Access（目录授权）只在安全上下文可用**：手机连的局域网地址页面没有该能力，扫描等操作须在 `127.0.0.1:5273` 上做。
