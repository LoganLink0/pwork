# 配置文件化设计（prefs.json）

- 状态：设计稿（2026-11-16 立项，用户拍板）——实施前需过审
- 动机：用户设置散在 WebView2 的 localStorage（按 origin 隔离 + leveldb 存储），两个已发生的真实痛点：①dev 壳（127.0.0.1:5273）与桌面版（tauri.localhost）origin 不同，配置互不可见——「dev 里测的配置桌面版没有」与「桌面版配置 dev 看不到」反复造成困惑；②leveldb 在进程被强杀时会丢近期写入（0.1.23 期间真实发生过：主题/AI 接入偏好丢失，用户视角即「配置又丢了」）

## 一、范围（迁什么）

| 类别 | 现存储 | 迁移后 | 说明 |
|---|---|---|---|
| 主题偏好 | localStorage `pwork-theme` | prefs.json `theme` | light/dark/auto |
| AI 接入配置 | localStorage `fupan-coach` | prefs.json `coach` | **Key 不迁**——Key 只在 gateway.env（既有安全边界，0.1.18 定稿），coach 里 viaGateway 模式本就不存 Key |
| 键位 | localStorage `pwork-keybinds` | prefs.json `keybinds` | 7 个键位 |
| 自动备份偏好 | localStorage `pwork-autobackup` | prefs.json `autoBackup` | 开关/周期/上次时间 |
| 胶囊岛位置 | localStorage `pwork-isle-pos` | prefs.json `islePos` | 模式与坐标 |
| 通知偏好/侧栏折叠等杂项 | localStorage 各键 | prefs.json 逐键平移 | 除草稿（body 在库）、最近打开（在库）外的纯 UI 偏好 |

**不迁**：库内数据（速记/条目/待办/复盘——IndexedDB→SQLite 主库，0.1.19 起已文件化）；草稿；Key（gateway.env）。

## 二、存储形态

- 落点：`AppData/com.pwork.workbench/prefs.json`（与 pwork.db、gateway.env 同级）
- 读写：经 Rust 命令 `prefs_read`/`prefs_write`（原子写：tmp+rename，同 backup_file_io 纪律）；PWORK_DATA_DIR 隔离变量照常生效
- 写入策略：整文件读改写（配置总量 < 10KB）；每次写全量落盘
- **dev 与桌面天然同套**：两者读同一数据目录文件——「dev 里配的桌面版没有」从机制上消失

## 三、读写层设计

- 新建 `app/src/engine/prefsFile.ts`：`readPrefs()` / `writePrefs(patch)`（合并写）+ `usePrefsFile()` 订阅
- 迁移兼容：启动时若 prefs.json 不存在且 localStorage 有旧键 → 一次性平移进 prefs.json（旧键保留 30 天不删，防回退）；localStorage 读取函数改为「先读 prefs.json，无则回落旧键」——读写两端兼容期一个版本
- 失效回退：prefs.json 损坏/读失败 → 忽略并按默认值跑 + recordError 留痕（不崩应用）

## 四、消费方迁移清单（按模块）

| 模块 | 函数 | 改动 |
|---|---|---|
| appearance | loadTheme/saveTheme | 读改走 prefsFile；syncThemeFromStore 的 storage 监听改为跨窗事件（emit `pwork-prefs-changed`） |
| coach | loadCoachConfig/saveCoachConfig | 同上（viaGateway 归一逻辑保留在 load 内） |
| keybinds | loadKeybinds/saveKeybinds | 同上；保存后重注册全局热键的链路不变 |
| autoBackup | loadAutoBackup/saveAutoBackup | 同上 |
| isle 位置 | localStorage POS_KEY | 同上 |
| 快速通道 | 首访偏好等杂项 | 逐键平移 |

## 五、测试与验收

1. 迁移用例：localStorage 有旧键 → 启动 → prefs.json 出现同值
2. 写入用例：saveTheme → prefs.json 更新 → loadTheme 回读一致
3. 跨端用例：桌面写 → dev 读到同值（同数据目录）
4. 损坏用例：prefs.json 写坏字符 → 按默认值跑 + recordError
5. 回归：全量测试 + tauri build 冒烟

## 六、不做的事

- 不迁库内数据（主库已文件化）
- 不迁 Key（gateway.env 既有边界）
- 不做配置项 UI 编辑器（本轮只做存储层迁移，界面无感）
