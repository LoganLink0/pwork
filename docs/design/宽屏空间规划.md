# 宽屏空间规划（页面利用率整改设计稿）

- 状态：设计稿（2026-11-17，用户授权按专业建议出方案，过目后执行）
- 问题：宽屏（1920/2560）下正文列限宽居中（--content-w: 1200px），两侧是纯底色空白——图1 红框即此。正文行宽约束本身正确（一行中文 40 字上下可读性最好），错的是宽度没有被花在任何地方
- 成熟实现的共同策略：**大屏不拉长正文，把宽度花在并列栏位**——留白被功能性面板占据，不是空着

## 一、成熟产品的四种空间模式

| 模式 | 代表 | 空间结构 | 适用界面类型 |
|---|---|---|---|
| 收件箱处理流 | Superhuman / Gmail / Shortwave | 导航 + 宽列表 + 概览/详情栏 | 逐条分诊、看完即处理的流水线 |
| 三栏任务工作台 | Linear | 导航 + 宽列表/看板 + 详情面板 | 任务、工单、条目管理 |
| Bento 仪表盘 | 各类产品首页 / Grafana | 卡片网格自适应铺满宽幅 | 概览、统计、入口聚合 |
| 表单+预览向导 | 部署平台 / 编译器 playground | 左表单 + 右实时预览/历史 | 有产出的操作流 |

PWORK 四模块的本质映射：日报=收件箱分诊流；待办/条目库=三栏工作台；首页/回路仪表盘/输出主页=Bento；输出子页=表单+预览。

## 二、统一骨架（先定骨架再逐页填）

- 新增宽幅容器类 `.content-wide`：max-width 1560px，内部 `主列 1fr + 副列 300px` 两栏 grid，副列 sticky 跟随滚动
- 宽度分级：≥1440px 出副列；1024–1439px 副列隐藏（关键数字并入页头）；<1024px 单列现状不动
- 现有 `--content-w: 1200px` 保留，继续管单栏阅读型页面（帮助/设置/云端/表单工具页）——不是所有页面都该宽，表单和文档拉宽了反而难读
- **副栏内容纪律**：只放「与当前列表状态相关的实时信息」——概览数字、统计分布、快捷筛选、高频操作。静态说明文字一律进帮助页，副栏放说明就是凑数，用两次就没人看了

## 三、逐页规划

| 页面 | 现状 | 方案 | 批次 |
|---|---|---|---|
| 信息日报 | 单列窄条（最痛，图1） | 宽幅双栏：主列=日报卡片列表拉宽；右栏「今日概览」=抓取状态（信源数/成败）、条数与分层分布条（必看/可看/可略）、快捷筛选（只看必看/未处理/带音频）、导出入口从页头聚拢到栏内 | 一 |
| 待办 | lanes 三列已较宽，schedule 单列 | 宽幅双栏：右栏「目标与节奏」=目标进度条列表、本周完成热力、到期分布；lanes 视图 ≥1440 三列+右栏，schedule 主列拉宽 | 一 |
| 条目库 | 单列按月列表+卡内展开详情 | 宽幅双栏：右栏「库概览」=当月入库数、评分分布（多推/少推）、筛选器从页头聚拢；卡内「详情」改右栏常驻详情面板放第二批二步（结构改动大，先概览栏） | 二/三 |
| 回路仪表盘 | container 单列 | Bento 宽幅：卡片网格 auto-fill 自适应 2→3 列 | 二 |
| 输出主页 | 单列入口列表 | Bento 宽幅：产出入口卡片网格 | 二 |
| 输出子页（周报/PPT/文章/调研） | 表单单列 | 左表单+右栏实时预览/历史产出——每页内容不同逐个设计，单独批次 | 三 |
| 信源 | 单列列表 | 右栏=选中信源详情+抓取历史，单独批次（结构改动） | 三 |
| 首页 | 瓦片+模块卡 | 宽幅自适应列数（瓦片区宽屏 2→3 列），随二批顺带 | 二 |
| 速记 | 已是列表+编辑器双栏 | 不动 | — |
| 设置/帮助/云端 | 左导航+右内容 | 单栏阅读型，维持 1200px 不动 | — |

## 四、执行分批

- **第一批**：`.content-wide` 骨架 + 信息日报右栏 + 待办右栏（最痛两页出效果，副栏内容纪律与响应式规则同时立住）
- **第二批**：条目库概览栏、回路/输出/首页 Bento 网格
- **第三批**（结构级，单独过审再动）：条目详情右栏化、输出子页预览栏、信源详情栏

验收：每一批 1440/1920 宽屏截图对比 + 1024/768 窄屏回归（副栏消失后信息不丢）+ 全量测试。
