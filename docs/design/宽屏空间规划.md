# 宽屏空间规划（页面利用率整改设计稿 · v3 全页面覆盖）

- 状态：设计稿 v3（2026-11-17，用户三条追加反馈后修订：①信源自检与订阅发现进右栏 ②设置/帮助纳入改造 ③工具子页纳入改造；流程=规范→示意图→通过后执行）
- v1 教训：第一批只做了日报+待办两页，用户指出「要求所有页面都做」——本版按 27 条路由全量决策
- 问题定义：宽屏（1920/2560）下正文列限宽居中，两侧是纯底色空白。正文行宽约束本身正确（一行中文 40 字上下），错的是宽度没有被花在任何地方
- 成熟实现的共同策略：**大屏不拉长正文，把宽度花在并列栏位**——留白被功能性面板占据

## 一、五种形态（全站分类标准）

| 形态 | 结构 | 判据 | 代表 |
|---|---|---|---|
| A 宽幅双栏 | 主列 1fr + 右栏 300px sticky | 「列表/流水线 + 实时概览」类 | 日报、待办、信源、条目库、目标、外部数据、云端、回路主页、认知资产、设置、帮助 |
| B 宽幅网格（Bento） | 卡片网格 auto-fill 2→3 列，无右栏 | 「概览/入口聚合」类，整页即概览 | 今日、输出主页、处理工具箱 |
| C 表单+预览双栏 | 左表单 + 右预览/说明/历史 | 「有产出的操作流」类 | 一键成稿、工具子页、周报导出、朗读、数据卡、PPT 撰写、文章草稿、调研分析 |
| D 双栏既有 | 列表+编辑器，已达宽幅形态 | 不动 | 速记 |
| E 全屏专注 | 不动 | 向导/会议室/欢迎页要的就是无干扰 | 复盘向导、会议室、欢迎引导 |

## 二、统一规则（v1 定稿沿用）

- 宽幅容器 1560px = 主列 1fr + 右栏 300px sticky；宽度分级：≥1440 出右栏，1024–1439 右栏隐藏（`.only-wide` 隐藏 / `.only-narrow` 兜底），<1024 单列现状
- 右栏内容纪律：只放「与页面主体相关的实时信息/诊断/导航」——概览数字、统计分布、快捷筛选、高频操作、页内目录；静态长文说明不进右栏
- Bento：≥1440 三列、1024–1439 两列、<768 单列
- 已落地（第一批）：骨架 + 日报右栏 + 待办右栏
