# PWORK 开发复盘：踩坑实录与解法

> 项目：个人工作台 PWORK（W0–W5 全程 + W5 后迭代：输出深化、外部数据三件套、任务/目标交互定稿、文章草稿、开放推送接口；2026-10 分发加固：错误系统/评分调参闭环/Tauri 桌面壳/1.0.0 定版）
> 范围：app（React 19 + Vite 8 + Dexie，319 测试）+ worker（Cloudflare Workers，19 测试，已部署上线）+ 文档基座（八件套规范）+ 打包分发
> 用途：给后来者（包括未来的自己）避坑。格式沿用 FUPAN《开发复盘》：**现象 → 根因 → 解法 → 预防**。
> 关系：本文是 FUPAN《开发复盘》的续篇——多处旧坑在新环境**原样复现**，文中标注「复现：FUPAN x.x」。

---

## 一、代码与架构类

### 1.1 速记并发更新竞态：同批次连点互相覆盖（测试先行当场抓住）

- **现象**：store 测试"连续两次 update 不同字段都落库"失败——后一次更新基于旧值整体覆盖。
- **根因**：`update` 的读-改-写（getNote → saveNote）不在同一事务里，两个并发更新交错执行。
- **解法**：`updateNoteFields` 包进 `db.transaction('rw', ...)`，读改写原子化。
- **预防**：复现：FUPAN 1.2（函数式更新）。这次证明 Zustand 层做了函数式还不够——**落库也要事务化**。连点回归测试永久保留。

### 1.2 命令面板"新速记"不参与查询过滤（测试抓不到，浏览器抓到）

- **现象**：面板里输入搜索词后按 Enter，永远落在"新速记"动作上而不是用户看到的匹配结果。
- **根因**：快速动作数组写死不过滤；jsdom 集成测试只走了点击路径，Enter 键路径只在真实浏览器验证时暴露。
- **解法**：快速动作与页面/速记同样按查询词过滤——**有查询词时 Enter 必须落在用户看到的匹配项上**。
- **预防**：凡是"列表 + 默认选中项"的交互，测试必须覆盖"有查询词时的默认项语义"。

### 1.3 OtPicker 无限重渲染崩溃（迁移中自己引入的）

- **现象**：完整版向导逻辑步整树白屏，控制台 "Maximum update depth exceeded"，错误定位 `<OtPicker>`。
- **根因**：zustand selector 内联 `items.filter(...).slice(0,8)`——每次调用返回新数组，引用比较永远不等 → setState 循环。
- **解法**：selector 只取 `s.items` 稳定引用，派生用 `useMemo`；注释留档。
- **预防**：复现：FUPAN 1.2 的 zustand 变体。升级为纪律：**selector 里禁止任何创建新引用的表达式**（filter/map/slice/对象字面量）。

### 1.4 useNavigate 用在渲染 Router 的组件里（自己引入）

- **现象**：首访重定向一加，全应用白屏；控制台 `useNavigate() may be used only in the context of a <Router>`。
- **根因**：App 组件本身渲染 `<HashRouter>`，在它内部调 useNavigate 位于 Router 上下文之外。
- **解法**：抽 `FirstRunRedirect` 空组件放进 `<HashRouter>` 内部。
- **预防**：壳组件自身要导航时，重定向逻辑必须下沉为 Router 内的子组件。

### 1.5 跨午夜日期跳变炸出 8 个测试（最重要的产品 bug，真实环境暴露）

- **现象**：昨晚 23:40 全量 189 测试全绿；次日（日期跳到 09-01）同一套代码 8 个测试全崩——今日速记数 0、Digest 空、条目统计错位。
- **根因**：时间戳按 UTC ISO 存储，"今日"筛选用 `iso.slice(0, 10)` 截取日期串——UTC+8 的本地 0:00–8:00 之间，UTC 日期还是"昨天"，所有"今天"统计错位一天。
- **解法**：新增 `localDateOf(iso)`（先转 Date 再取本地字段），替换全部三处裸切；纪律行升级为"**本地日期比较一律用 localDateOf/todayLocal，禁裸 toISOString 与 iso.slice(0,10)**"。
- **预防**：复现并深化：FUPAN 1.4。深层教训：那篇复盘说"禁裸 toISOString"，但**没禁 `toISOString().slice(0,10)`**——漏洞换了形态复活。日期规则必须工具函数化到"没有裸写法可用"。

### 1.6 采集评分链的时区一致性（worker 例外）

- **决策**：本地侧"按本地日"全部走 localDateOf；worker 云端 cron 按 UTC 日跑——服务端按 UTC 是预期行为，两侧不追求一致，文档写明。
- **预防**：跨端项目要显式回答"每一侧的'天'是什么天"。

### 1.7 条件调用 Hooks（FUPAN 遗留，这次被 lint 拦截）

- **现象**：W3 迁移后 oxlint 报 2 个 error——LogicTree 的 `useTreeOps`、StepLogic 的 `useState` 都写在 `if (!draft) return null` 之后。
- **根因**：FUPAN 开发时的 oxlint 未启用 rules-of-hooks（其复盘 1.1 明说"靠人肉发现"），代码带病运行至今（条件分支实际稳定所以没炸）。
- **解法**：Hook 全部提前到早退之前；LogicTree 依赖的 `setTree` 是函数声明（提升），提前引用安全。
- **预防**：复现：FUPAN 1.1。**新工程第一步就把 `react/rules-of-hooks` 设为 error**——这条规则欠的债会原样传给下一个仓库。

### 1.8 迁移批量替换误伤 import 路径

- **现象**：路由改写 `s|/wizard|/review/wizard|g` 把 `../components/wizard/StepComparison` 的模块路径也改成了 `components/review/wizard/...`，12 个 TS2307。
- **根因**：全局正则不区分"路由字符串"与"模块相对路径"。
- **解法**：tsc 当场抓住；针对性回改 `components/review/wizard/` → `components/wizard/`。
- **预防**：批量替换前先 grep 目标模式的所有形态；替换后立即 tsc。迁移类操作"编译器就是验收测试"。

### 1.9 模块相对路径深度记错（两次）

- **现象**：`pages/` 下的文件用 4 级 `../../../../`、`components/tools/` 下的用 3 级——各错一次。
- **预防**：无捷径，靠 tsc；但可以把"深度=目录层数"写进迁移 checklist。

### 1.10 桥接后跨模块 store 不刷新（e2e 抓住）

- **现象**：复盘归档后 IndexedDB 里 tasks 表有记录，但任务页显示 0 条。
- **根因**：useTasks 是启动时加载的内存快照；归档发生在回路模块内，不通知任务库 store。
- **解法**：归档桥接完成后主动 `useTasks.getState().load()` + 任务页挂载时重载兜底。
- **预防**：跨模块写操作必须回答"谁的内存快照需要失效"。localStorage 跨标签页都 有 storage 事件，模块间也要有等价机制（哪怕只是主动 load）。

### 1.11 全局 CSS 类名冲突让迁移页面布局崩坏

- **现象**：壳的 `.page-head`（flex 行）会打断回路页 `.page-head`（块状 + kicker 堆叠）；`.input` 两套定义。
- **解法**：ui.css 全量作用域化到 `.review-root`（脚本处理 @media 嵌套/多行逗号选择器/@keyframes 跳过），base.css 冲突规则以 `.review-root .page-head` 覆写。
- **预防**：迁移前端面调研类名交集（grep 顶层选择器排序对比）；**作用域化是迁移的安全网，不是可选项**。

## 二、测试与验证类

### 2.1 vitest 未开 globals → RTL 不自动 cleanup → 18 个测试连环崩

- **现象**：一个用例失败后，后续所有集成测试超时（3s 上限全打满）。
- **根因**：没开 `globals: true` 时 RTL 不自动 cleanup——失败的 App 实例还挂着，GlobalShortcuts 监听器层层叠加。
- **解法**：setup.ts 显式 `afterEach(cleanup)`。
- **预防**：看见"大面积超时"先怀疑测试间污染，再怀疑代码（呼应 FUPAN 2.2"先确认单跑"）。

### 2.2 选择器三败模式的 W5 新变体

- accessible name 带计数：侧边栏"速记"链接实际名称是"速记 1"——精确匹配挂，正则解。
- 图标字符（✎ ⚡）不计入 accessible name 但影响直觉。
- 断言文本与副标题撞词（"排错"同时出现在副标题和 h2）→ 一律 `getByRole('heading', { name })`。
- 复现：FUPAN 2.1。**规则不变：断言用唯一片段 + 作用域 + 角色**。

### 2.3 受控 input 在测试里直接赋 value 不触发 onChange

- **现象**：evaluate 里 `input.value='x'` + dispatchEvent 后 React 状态没变（value tracker 认为"值没变"）。
- **解法**：优先用测试工具的 fill；必须原生时用 prototype setter + input 事件（FUPAN 2.3 原样复现）。
- **附带教训**：绕过 React 的注入会让"过滤后的 Enter"落到错误的列表项上——测试手段本身会制造假象。

### 2.4 测试自身预期写错（非产品 bug，如实记）

- digestDates 断言漏了合法的 2020 条目；信源表单 `<label>` 嵌 `<button>` 导致可访问名异常（语义错误，改为普通容器）；差异行默认"如期完成/做得好"已预选但断言当作未选。
- **预防**：失败先问"断言对不对"，再问"代码对不对"——本项目两者比例约 1:1。

### 2.5 日期跳变是天然的时区回归测试

- 正面经验：昨晚全绿、今晨全崩的 8 个失败，**恰好是时间类 bug 的完整回归集**。
- **预防**：时间相关测试要含"23:59 与 00:30"两个用例；CI 若有条件，分别在 UTC 16:00 前后各跑一次。

## 三、环境与工具类（Windows 重灾区）

### 3.1 Windows + Vite watcher 竞态（复现：FUPAN 3.1，频率最高）

- **现象**：文件已保存，served 内容还是旧的——"路由不生效""组件是旧版"。touch 单文件有时无效。
- **解法**（按代价排序）：curl 验证 served 内容 → touch 改过的文件 → 按端口杀进程重启。本项目 curl 验证至少 4 次定位问题，重启 2 次。
- **预防**：**"改完必须 curl 验证 served 内容"已固化进验证流程**——这条是本项目性价比最高的纪律。

### 3.2 后台进程 = 孤儿进程（复现：FUPAN 3.2）

- **现象**：TaskStop 杀掉 bash 壳，vite 子进程存活继续占端口；旧实例服务旧代码，新实例起不来。
- **解法**：`netstat -ano | grep :端口` → wmic 确认身份（**杀之前必查是谁**——用户自己的 FUPAN 实例也在跑）→ taskkill //F //PID。
- **预防**：项目专用端口（5273）+ 启动器脚本统一管理起停。

### 3.3 端口冲突先查身份再动手

- 5173/5174 被占，查明是用户自己的 FUPAN dev server——**不盲杀**，PWORK 固定 5273 并写进 vite 配置与启动器。
- **预防**：每个项目一个专属端口段，README 写明。

### 3.4 cmd 批处理 + 中文 = 定时炸弹（用户实际踩爆）

- **现象**：双击 部署向导.cmd，满屏乱码 + "不是内部或外部命令"碎片（'lare'、'base_id组'——命令被从多字节字符中间劈开）。
- **根因**：cmd 按 GBK 解析批处理；`chcp 65001` 挡不住解析错位（UTF-8 多字节被按 GBK 切分）。
- **解法（根治）**：**批处理只留纯 ASCII 两行壳**（chcp + 调 node），全部中文提示与逻辑搬进 `scripts/deploy-wizard.mjs`——Node 的 UTF-8 输出/输入/正则原生可靠。
- **预防**：**给别人的 .cmd 文件里永远不写中文**。这条应与"给别人的 .cmd 不依赖用户 PATH"并列。

### 3.5 IExpress 打包三连败（GUI 错误无法在 CLI 捕获）

- 败因一：相对路径传 SED——IExpress 内部进程不继承工作目录，弹"SED 不存在"（弹窗，CLI 端 rc=0）。
- 败因二：SED 里多余的 `)` 行被解析成打包文件名（弹窗 "Unable to find tools\)"）。
- 败因三：**IExpress 每次运行会把旧格式 SED 原地改写为 v3 并可能丢字段**（TargetName 静默变空 → 假成功无产物）。
- **解法**：绝对路径 + 按 IExpress 自己生成的 v3 骨架写（[SourceFiles0] 只放 `%FILE0%=`）。
- **预防**：IExpress 报错全靠 GUI 弹窗，脚本化打包必须"跑完立刻验证产物存在"；SED 用它生成的那份做模板。

### 3.6 启动器批处理的 %PORT/ 笔误（用户实际踩爆）

- **现象**：双击启动器弹"Windows 找不到文件 'http://127.0.0.1:PORT/'"。
- **根因**：`%PORT%/` 少了收尾百分号，cmd 展开失败把字面量当路径。**我的 e2e 没抓到**——服务拉起那半段代码是对的，弹窗发生在打开浏览器那半段。
- **解法**：修正为 `start "" "http://127.0.0.1:%PORT%"`，重打包重测。
- **预防**：批处理变量引用错位是静默失败；"能跑通主流程"不等于"没有副作用弹窗"。e2e 要覆盖完整用户路径（含打开浏览器）。

### 3.7 依赖版本写死不存在的 ETARGET

- `@cloudflare/workers-types@^4.20260801.0` 不存在 → npm install 整体失败。解法：`^4`。
- **预防**：新工程依赖让 npm 解析最新，不手写精确版本。

## 四、真实环境类（测试环境永远替不了）

### 4.1 rsshub.app 大陆不可达：示例源全军覆没

- **实测**（本机 curl 三通路）：rsshub.app 直连超时；rssforever 镜像 200 但 CORS 回显自身域名（浏览器直抓仍被拦）；rss2json 服务端转接可用。
- **解法**：抓取链改三级（直连 → rsshub.app 自动换镜像 → rss2json）；示例源换成 5 个实测可用的原生 RSS（阮一峰/少数派/HNRSS/Solidot/GitHub Blog，逐个经 rss2json 验证）。
- **预防**：**凡是依赖外部网络的默认值，先在目标网络实测再写死**。为此在引擎里保留了"逐源失败原因"（健康列），排错有据。

### 4.2 时区不是玄学，是产品参数

- 本地侧按本地日（localDateOf）；worker 云端按 UTC 日（cron 语义）——两侧显式不同，文档写明。
- 呼应 1.5。

### 4.3 agent-browser 测试 profile 跨会话不持久

- **现象**：上次会话抓的 43 条目在新会话里消失（IndexedDB 清空），e2e 断言全空。
- **解法**：e2e 前先探库（indexedDB.databases + count），按当前会话的真实数据设计路径；需要存量数据就在会话内现造。
- **预防**：浏览器自动化**不要假设上一次会话的状态**——真实用户的浏览器反而持久，两侧都要测。

## 六、如果重来：最重要的建议

1. **先定日期工具，再写第一行业务代码**：localDateOf/todayLocal 进 datetime 模块，lint/评审禁裸 slice——1.5 那种"每天早上坏两小时"的 bug 不会存在。
2. **状态库 selector 纪律工具化**：能上 eslint-plugin 的规则绝不上人眼；zustand 项目考虑 selector 深比较中间件。
3. **给别人的每个脚本都先在干净终端跑一遍**：PATH/编码/弹窗三类问题只在"非开发者环境"现形。
4. **浏览器 e2e 不是单测的重复，是另一双眼睛**：本项目三个真 bug（1.2 面板、1.10 刷新、W4 下载路径）只有浏览器层能抓。
5. **迁移 = 冻结 + 平移 + 回归网**：tag → 结构平移（不改行为）→ 原测试当回归网 → 再叠加新能力。W3 一次成功全靠这个顺序。
6. **外部依赖先实测再写进默认值**：信源、公共 API、公共实例，全部"目标网络验证过的"才算数。

### 3.8 workers.dev 域名在大陆被阻断 → 三层架构应对

- **现象**：Worker 部署成功（api.cloudflare.com 可达），但浏览器访问 `*.workers.dev` 端点超时（ERR_CONNECTION_TIMED_OUT）——本地"同步"连不上云端。

- **预防**：面向大陆的云功能，设计时就把"控制面（api.cloudflare.com）"与"数据面（workers.dev）"分开评估可达性，数据面永远准备第二条路。

### 3.9 wrangler 4 移除了 `subdomain register` → 直接调 Cloudflare API

- **现象**：新账号首次部署报"You need to register a workers.dev subdomain"，且 wrangler 在非交互上下文自动答 "no"（spawnSync 场景）。
- **解法**：读取 wrangler 本地 OAuth 凭据（`%APPDATA%\xdg.config\.wrangler\config\default.toml`，任何 wrangler 命令运行后会自动刷新），直接调 `PUT /accounts/{id}/workers/subdomain` 注册子域名；随后 `wrangler deploy` 正常。
- **预防**：CLI 工具删掉的命令，API 还在——带着"OAuth 凭据就在本地"的意识翻配置文件。另：wrangler 在 spawnSync 的 shell 链路里判为非交互，所有确认提示都会静默答 no——**自动化调用 wrangler 时优先选无确认路径**。

### 1.4 补充：localDateOf 全量落地后的剩余盲区

- worker 侧刻意保留 UTC 日（服务端语义），两侧"天"不同是**文档化的设计**而非疏漏；排查数据问题时先问"这一侧的天是什么天"。

## 补记二（W5 交互打磨期新增，2026-09-02）

> 覆盖 PPT 导出、待办/目标交互重构、设计系统落色三轮。这一轮的坑从"代码跑不跑"转向"设计想没想"——多数不是技术故障，而是设计缺口被用户当场指出。

### 1.12 pptxgenjs fontFace 带引号 → PPT 文件整体损坏

- **现象**：导出的 PPT 在 PowerPoint 里直接报"内容有问题"无法打开。
- **根因**：字体名写成 `"Microsoft YaHei"`（带引号），pptxgenjs **不转义 XML 属性**，引号原样拼进 attribute 产生非法 XML。
- **解法**：FONT 常量去引号只留单值 `Microsoft YaHei`；顺带把图表改回单系列标准形态。
- **预防**：给生成器库传字符串参数先问"这个值会被拼进什么格式"；XML 属性类参数一律进常量集中审查。产物类功能必须有"能被目标程序打开"的验收——解析 zip/xml 或人工打开一次都行，"生成成功"不等于"产物有效"。

### 1.13 待办交互没有状态机：状态在、入口不在、规则互相打架

- **现象**（用户三连问）：待办怎么调分类？点击某区域怎么自动闭环了？目标"已放弃"是怎么设计的？
- **根因**：三层缺口叠加——① `dropped` 状态数据层支持但页面无任何入口（不可达状态）；② 分类调整 `setLane` 在 store 里但 UI 入口在重构中丢失（见 1.15）；③ 分诊引擎里"到期→一类"优先级高于手动设置，用户手动调整会被自动规则悄悄改回——用户意志低于自动规则，方向反了。
- **解法**：状态流转矩阵定稿并写进 PRD §4.5.1——复选框是唯一状态开关（勾选=闭环/达成，再点=恢复）；放弃=留底可恢复，删除=软删除；分类下拉手动优先于自动分诊；待办/目标两页同一套规则。
- **预防**：**先写状态机再写按钮**：每个状态列出"从哪来、到哪去、哪个按钮触发"，反向审计每个状态是否可达、每个按钮属于哪个转移。规则冲突时明确排序（用户手动 > 自动规则）并写进引擎注释。

### 1.14 TSX 里的类名在 CSS 中从未定义：`.checkbox` 无样式占满整行成误触热区

- **现象**：用户反馈"点击某个区域还会自动闭环"——任务行顶部一整条横线都是完成按钮。
- **根因**：`.checkbox`、`.task-card`、`.t-due`、`.origin`、`.stats-line` 在全部样式文件中 **0 条定义**（grep 验证）。无样式的 div 是块级元素占满整行宽度，绑在它上面的 onClick 就成了整行热区。两行布局重构时给 `.task-row` 写了 `align-items/padding` 增量，却没有 `display: flex` 基础——在假设存在的基础样式上做增量。
- **解法**：补齐全套定义（flex 基础、20px 方框复选框、卡片容器、期限色、来源徽章、统计行）。
- **预防**：这类问题 build/test/lint 全部不报，**只有真实渲染能暴露**。重构提交前跑一遍"类名定义完整性"检查（提取 TSX className → grep CSS 定义数，0 条即红）；新布局假设某基础类存在时，先打开 CSS 确认再写增量。

### 1.15 重构丢功能：两行布局把分类调整入口弄丢了

- **现象**：上一版有（虽然隐蔽的）"挪一下"按钮，重构后整个页面没有任何调分类的入口。
- **根因**：按新布局重写渲染函数时，旧 UI 承载的能力没有清单对照，`setLane` 从 import 到 JSX 一起被删。
- **解法**：与 1.13 一起补回，并升级为显式分类下拉。
- **预防**：**重构 UI 前先列旧版交互元素清单**（每个元素对应什么数据操作），重构后逐项对照"还在不在"。功能丢失不会被任何测试抓到——测试只测被测的那条路径。

### 1.16 占位从未实装：按钮写着"W3 开放"，W5 都过了还是点不了

- **现象**（用户连问两个）：速记编辑器"转待办/挂到复盘"两个按钮永远按不动——代码里写死 `disabled`，提示语还是"W3 上线后开放"，而 W5 早已交付。全面排查又挖出一批同类：命令面板"新建复盘（W3 迁入后开放）"、侧栏页脚"W1 · 壳 + 速记"、帮助页把已上线的处理/输出写成"规划中"、首页"AI 两级筛选 W4 接入"（本地按设计就是规则链，AI 在云端）、`Note.links.itemIds` 三向挂接里唯一没有任何写入方向。
- **根因**：占位提示写在 W1/W2 时期，本身没问题；问题在**对应功能上线时没有回头移除这些提示**——每个新模块交付时只验证自己的功能，从不检查这次上线让哪些旧占位失效了。这与 1.15（重构丢失功能）属于同一类：都是缺少一次对照检查。
- **解法**：逐个实装或诚实化——转待办/挂到复盘接通（后者需要 ReviewRecord.noteIds 全链贯通）；陈旧标注/文案全部更新；`links.itemIds` 补上唯一缺失的写入路径（条目卡"写速记"）。
- **预防**：**模块上线时做一次"占位清零"检查**：grep 全库 `disabled` 硬编码、"后开放/规划中/接入"类提示语、以及"只有展示没有写入"的状态字段（如 links 计数）。剩余占位必须带路线标注（如 O4 草稿/O5 视频），做到占位可枚举、全部显式。

### 1.17 只有展示没有写入的"假状态"：Note.links 三向挂接断了两向

- **现象**：速记详情展示 `links: items N · reviews N · tasks N`，但三个计数里两个永远是 0——`links.taskIds`、`links.reviewIds`、`links.itemIds` 全库没有一个写入方，转待办/挂到复盘/条目写速记三条路都没建。
- **根因**：展示层照数据模型写了，但每条"产生挂接"的用户路径（速记转任务、速记挂复盘、条目写速记）实现时都只建了正向对象，没回写反向挂接。
- **解法**：三条路径各自补回写；`ReviewRecord` 增加 `noteIds`（字段只增不删），挂载时双向对齐。
- **预防**：**凡是界面上展示的计数/状态字段，必须能指出"哪个用户动作会改变它"**——指不出来的就是假状态，要么补路径，要么删展示。

### 3.10 sed 中间态被 HMR 缓存 → 待办页白屏（3.1 的最痛变体）

- **现象**：多处 sed 批量改 Tasks.tsx 后页面白屏，控制台 `ReferenceError: doneList is not defined`——但源文件里已经没有 doneList。
- **根因**：多步骤 sed 只完成一半引用替换（页面吃到中间态），Vite HMR 把这个中间态缓存进模块图；之后源文件改对了，浏览器仍用缓存模块。
- **解法**：curl 验证 served 内容确认源已正确 → 硬刷新清 HMR 缓存。
- **预防**：3.1 的三连升级版：**批量编辑 → curl 对比关键内容 → 硬刷新**；多文件批量改优先写脚本一次性完成，不用交互式多次 sed。

### 2.6 浏览器自动化的四个新坑（IAB + React 19 + confirm）

- **fill() 设置了 DOM value 但不触发 React onChange**——输入框回车后 value 不清空 = 状态没更新 = 提交根本没跑；真实键盘逐字输入（type）正常。判定技巧：**回车后输入框是否清空**就是"提交是否发生"的免费探针。
- **locator.click 卡在可操作性等待**（元素可见可命中仍超时）→ 用 evaluate 取 `getBoundingClientRect` 中心点，坐标点击兜底。
- **window.confirm 同步阻塞**：click 命令 30 秒超时**恰恰说明弹窗已弹出**——先 getJsDialog 处理，别急着重试点击。
- **deleteDatabase 被存活连接 onblocked 挂起**：重置隔离沙箱后必须硬刷新让 Dexie 重建连接，否则写入进旧实例（读旧写丢，且无报错）。
- **window.prompt 永久挂起**：既不弹窗也不返回，页面整页冻结——详见 3.12，结论是弹窗输入一律改行内编辑。
- **预防**：自动化脚本保留一条"真实键盘输入"路径；工具行为异常时先怀疑合成事件、再怀疑应用——但下结论要用独立证据（DOM 状态、数据库行数）。

### 七、设计与文案类（新维度：技术全绿 ≠ 设计合格）

#### 7.1 造词：把平话写成"看起来专业"的词

- **现象**（用户两次指出）：第一次是"分诊车道、四模态"等自造词直接出现在界面；第二次是界面文案清理完成后，向用户汇报修复成果时又使用了"静默断头路"这个自造词。
- **根因**：第一次数点后只把标准应用在了界面文案上，没有内化成自己的表达习惯——汇报和界面用的是两把尺子。概念密度高的词在说的人看来是精确，在听的人那里是负担。
- **解法**：界面文字和对用户的汇报使用同样的表达标准：直接描述事实和做法，不自造词，不用比喻。遇到已写出的自造词，当场给出平实说法："静默断头路"的平实说法是"点了没反应的按钮，界面也不提示"；"热区"是"点击范围"；"水位增量拉取"是"记住上次拉到哪，下次只拉新的"；"一致性收尾"是"新功能做了，有些页面还没跟上，补齐"。
- **预防**：写给用户看的每个词，假设对方没有读过任何文档，直接判断是否能看懂；看不懂就换成对事情本身的直接描述。工程文档和代码注释里可以保留必要的工程用语——那部分读者是改代码的人，不是用户。

#### 7.2 把"克制"执行成"无色"：设计系统在手却没接入

- **现象**：待办页灰黑一片，三栏分类无任何视觉区分；用户质疑"一定要这种完全没有颜色的风格吗？"
- **根因**：设计系统样例页明确定义了"零新增色，仅 3px 边线与 12px 标签"的模块标记纪律，但待办页开发时没回头对照——把纪律的"克制"理解成了"不用"。
- **解法**：零新增色接入——三分类识别色（一类=danger 红 / 二类=accent 琥珀 / 三类=cat-insight 蓝）用于栏卡 3px 顶边线 + 栏头圆点 + 计数 + 下拉；来源徽章按所属模块着色；状态徽章加底色；期限色阶（今天红/明天橙）。明暗双主题截图验证。
- **预防**：**新页面上线前对照设计系统样例页过一遍色彩与组件清单**；"克制"类纪律的正确执行是"有节制地用"，不是"不用"；颜色要承担区分职责——分类、来源、状态、期限四个维度各有各的色语义。

### 如果重来（续）

## 补记三（外部数据与信源扩容期新增，2026-09-02～09-03）

> 覆盖外部数据三件套（数据块/文件导入/推送接口）、信源扩容与部署验证、文章草稿 O4 实装。两起需要用户掏时间买单的事故都发生在这批，教训集中在"数据落地前的验证"与"环境差异"。

### 1.18 自动化写库不对账：参数错一个类型，814 条垃圾数据入库

- **现象**：导入 13 个信源时把数组参数传成了 JSON 字符串，循环按字符解构，向信源表写入 814 条地址为单个字符的垃圾行。
- **根因**：传参类型错误（string ≠ array）；更深层是**落库前后都没有对账**——第一轮执行只看了"没有报错"。
- **解法**：以"地址必须以 http 开头"清理全部垃圾行（清理前后对账：814 → 删 814 → 剩 0 条非法 → 正确导入 13 条），最终核对表内总数与名单一致。
- **预防**：自动化写库三步走——**预检（打印将写入的条数与样例）→ 写入 → 对账（前后计数 + 名单核对）**。这次能救回来靠的就是清理前后计数对得上；如果没打对账数字，垃圾数据会一直躺在用户库里。

### 3.11 同一网址，不同浏览器 = 不同存储（用户视角的"导入失败"）

- **现象**：13 个信源导入完成后，用户反馈"信源库没导入成功"——数据实际在，但导入进了测试用预览浏览器的存储，用户日常使用的浏览器是另一套独立存储。
- **根因**：IndexedDB 按"浏览器配置 + 网址"隔离。同一个 127.0.0.1:5273，预览浏览器和用户自己的浏览器互不相通。
- **解法**：给用户自己浏览器的路径——信源页「导入 JSON」选文件；同时把推荐信源包**内置进应用**（首页无信源时出引导横幅、信源页一键导入按钮），从根上消除"要把数据搬进哪个环境"的问题。
- **预防**：涉及数据落地的操作（导入/部署/清理），动手前先回答两个问题：**发生在哪个环境？用户在哪看结果？** 应用侧则尽量把默认值内置，减少需要用户搬数据的场景。

### 3.12 window.prompt 在内嵌浏览器永久挂起（用户环境直接卡死页面）

- **现象**：「记进度」的输入弹窗在预览浏览器中点击后整页冻结——prompt() 既不显示也不返回，JS 线程永久阻塞；同样的代码在常规浏览器正常。
- **根因**：内嵌浏览器对 prompt 的实现不完整：不弹窗、不返回、不报错。confirm 正常——三种弹窗行为并不一致。
- **解法**：记进度改为行内编辑器（输入框 + 保存/取消），顺带体验更好；全库排查确认无其他 prompt 使用。
- **预防**：**弹窗输入（prompt）一律不用**，改行内编辑；confirm 仅用于确认类。多环境分发的应用，交互原语要在实际分发环境逐一验证——"在标准浏览器没问题"不等于"在所有运行环境没问题"。

### 2.7 注入参数"收了不用" + 时间敏感断言（2.5 的第三变体）

- **现象**：信号触发的两个测试写完当天全绿，几小时后变红——期望"距上次复盘 12 天"，实际返回"13 天"。
- **根因**：两层。引擎 `collectSignals` 的函数签名接收 `now` 注入参数，天数计算处却直读 `Date.now()`——**注入参数收了不用**；测试断言又绑定了真实时刻（只在写入当天成立）。
- **解法**：引擎改用 `input.now ?? new Date()`；测试种子改为相对注入时刻的固定天数，永久确定。
- **预防**：凡声明支持注入的参数，函数体内禁止直读系统时钟（评审/自查点）；时间相关断言一律相对注入时刻表达。这次定位顺序是"先查断言、再查代码"——先确认了不是数据问题，才追到引擎，避免了把新功能误判为肇事者。

### 3.13 部署验证分层：发布成功 ≠ 本机可达（3.8 的操作化补充）

- **现象**：Worker 部署成功（Cloudflare 回执版本号），本机 curl 新端点 HTTP 000。

### 1.19 fetch 的超时信号会从 resp.text() 抛出，try 只包了 fetch 本身

- **现象**：立即抓取永久停在「抓取中」，无报错无结果；localStorage 单槽躺着 `rej: The user aborted a request.`。
- **根因**：`AbortSignal.timeout` 管整个请求生命周期——响应头已到、读体超时时中止错误从 `resp.text()` 抛出，而 try/catch 只包了 `fetch()` 调用。异常炸穿 runCollect → runFetchAll，`running:false` 的复位代码写在 Promise 后半段永远执行不到。
- **解法**：三层——① `resp.text()` 单独 try/catch 归为"该源超时"；② `runFetchAll` 整体 try/catch，任何失败都复位状态并把原因放进 FetchProgress.error 显示；③ RunSummary 记 elapsedMs，横幅直接报"上次抓取（11.3 秒）…"。
- **预防**：**带超时信号的 fetch，读体与请求本身要分别防护**；异步操作改状态的代码，"复位"必须放进 finally 或 catch（先问：中途炸了状态会不会卡死）。耗时类用户可感知操作，把时长记进结果里——用户问"多久了"不该需要查日志。

### 1.20 错误处理纪律：从"最后一条 localStorage 记录"到错误日志系统

- **决策**（用户拍板）：出错必须立即暴露（"崩溃给他看"），且持久记录哪里发生了什么。落地为四层：IndexedDB errorLog 表（上限 300 条最旧先删，Raw 层语义）+ 全局 error/unhandledrejection 捕获 + 顶部红色错误条（recordError 即弹）+ 设置页查看器（时间/类别/位置/消息/堆栈，可导出 Markdown 可清空）。渲染崩溃走 ErrorBoundary 出整屏崩溃页——**不白屏，白屏让人读不到日志**。
- **关键取舍**：引导期（index.html 内联钩子）的历史错误**静默搬运**入库——弹条只属于当前会话的新错误；约 140 处 `void fn()` 不逐点包 track，全局 unhandledrejection 网已覆盖且带堆栈，逐点包反而重复记录；启动路径的 load 用 track 是为拿到明确的定位标签。
- **预防**：新代码写 `void asyncFn()` 前想一句"它拒绝了谁知道"——答案必须是"全局网知道且用户看得见"；新增静默 catch 要在评审里说明为什么静默（读取侧防御可以静默，操作失败必须留痕）。

### 2.8 IAB 的 evaluate 跑在隔离世界：主世界监听器收不到它派发的事件

- **现象**：浏览器自动化里 `evaluate(() => window.dispatchEvent(new ErrorEvent(...)))`、`setTimeout(() => { throw ... })` 都到不了页面自己注册的 window 监听器；连 index.html 内联钩子（同在主世界）也不更新。jsdom 单测里同样的派发全通过。
- **根因**：CDP/Playwright 的 evaluate 在隔离世界（isolated world）执行——与页面共享 DOM 但 JS 全局对象隔离，它派发/抛出的错误不出主世界。
- **预防**：浏览器端验证"全局事件处理"这类主世界行为时，evaluate 派发**不是可信手段**；用真实用户路径（点按钮/真网络错误）触发，或接受 jsdom 单测 + 主世界副作用（如启动期代码）作证据。判定口诀：**先怀疑测试手段，再用独立证据下结论**（2.6 的延续）。

## 补记六（异机验收反馈批，2026-10-12）

### 3.18 flex-wrap 行末长文整块掉行：换行起点不一致的根源与统一标准

- **现象**：帮助页、四模块模型卡、名词表卡里，「标签 + 说明文字」的行出现两种起点——短文停在标签右侧列，长文整块换到下一行、从行首（标签下方）开始。用户报告为"换行后文字抬头位置改变"，要求统一成一个标准。
- **根因**：`.set-row` 是 `flex-wrap: wrap`。flex 的换行判定用 hypothetical main size（flex-basis:auto → max-content），长中文段 max-content 远超余宽，于是被放进新行独自占满；`flex-shrink` 只在行内生效，救不了跨行判定——所以"允许收缩"不等于"留在本行"。
- **统一标准（落在 shell.css，注释同源）**：`.set-row > .val:last-child { flex:1; min-width:0 }`——basis 0 永远放得进当前行，长文在标签右侧列内换行，各行与首行同列起步。行末还跟按钮的（快速上手"文字+去看看"式）val 用内联 flex:1+minWidth:0；夹在控件中间的 val（导出行、节序号）保持默认不动。
- **验证方法**：不靠截图猜——`evaluate` 量每行 label/val/row 的 `getBoundingClientRect().left`，全部 val 落同一列即达标。视觉模型看整页长图会漏读下半页（本次把存在的卡片说成"没有"），几何数字不会说谎。
- **同一批的两个小教训**：① 只读字段不进设置界面（"每日 Top N（只读）"被用户点名）——不能改的东西摆出来只会制造"为什么改不了"的疑问，产品参数放帮助页即可；② 标题要跟内容对账——「三步上手」下挂着 5 步，改成「快速上手」，标题里的数字是最容易过期的那类文案。

### 3.19 网关随服务自启：Windows 上连环踩的三个坑

- **现象链**：要"服务起了网关就得在"。第一版 vite 插件 `spawn(node, [脚本], { stdio: 'inherit' })` → 子进程秒退（码 3221225794 = 0xC0000142，DLL 初始化失败）；改 `fork + stdio: 'ignore'` 一次成功（宿主 stdout 是重定向文件时，子进程继承控制台会初始化失败——别继承）。
- **第二坑**：vitest 也走 vite.config 的 configureServer → 测试时拉起网关子进程，Vite 服务器退不出去（close timeout）。解法：`process.env.VITEST` 守卫，测试环境绝不自启。
- **第三坑**：vite.config.ts 分两次编辑（先改 import 再改调用体），vite 检测到第一次写入就重启，读到"import 已是 fork、调用体还是 spawn"的中间态，ReferenceError 崩掉。解法：改 vite 配置要么一次编辑成型，要么先停 dev 再改。教训泛化：**被 watcher 盯着的配置文件，原子化修改**。
- **顺手记录**：`child.unref()` + 服务器 close 钩子显式 kill 的组合，让子进程既不拖宿主退出、也不变孤儿。

## 补记九（2026-10-19 晚 · 手机窄屏巡检批）

### 3.22 全局规则假设了行结构：复合行的说明文字在窄屏被挤成"字柱"

- **现象**：390px 视口巡检发现两族问题。①周报/写作/调研/文章/欢迎页的「标签 + 按钮组 + 行末说明」行，说明文字被挤进按钮组换行后剩下的 25–111px 窄缝里逐字竖排（周报页最惨 25px）；②设置页错误日志查看器摘要行：位置列被容器裁掉一半、消息列宽度为 0（整列不可见）。
- **根因**：3.18 的全局规则 `.set-row > .val:last-child { flex:1; min-width:0 }` 隐含假设"行 = label + val 两个元素"；复合行里 basis 0% 的 val 抢到的是别的控件换行后剩下的缝——规则本身没错，是它的适用边界没写出来。errlog 摘要则是反面：各段全 nowrap 且 msg 无 `min-width:0`，省略号从未真正生效（超宽时只会被容器裁掉；现库消息都短，桌面端未暴露）。
- **修法**（全在 shell.css，桌面零改动）：≤768px 增补——①复合行说明（`.val:last-child:nth-child(n+3)`，即第 3 个及以后的行末 val）`flex-basis:100%` 下沉整行；②`label:empty` 隐藏（桌面对齐占位用，窄屏只会把按钮挤下去）；errlog 摘要 `flex-wrap:wrap`（整段折行）+ msg `min-width:0`。**全站枚举验证**：受影响 13 行逐一看过，全部是状态/提示文字，无误伤；桌面端副作用仅一处——错误日志长消息从"挤一行"变"整段折行"，可读性更好。
- **方法记录**：本环境（IAB 截图只能上传 CDN、模型看不到图）恰好逼出纯几何验证法——逐元素 dump `getBoundingClientRect` + computed flex，六种怪异布局全部精确重建，无需看图。3.18 "几何数字不会说谎"再添一证。另：掉行检测阈值 ±6px 对"按钮 + 垂直居中文字"行会误报（top 差来自居中而非换行），检测器要按行类型区分。
- **IAB 注入数据的坑**：Playwright `fill()` 设值后 React 受控组件不认（draft 状态为空，回车被空校验拦下），须原生 value setter + `dispatchEvent(input)`；`locator.click()` 卡可操作性时 `el.click()` 兜底（2.8 旧坑再现）。测试数据（3 任务/2 目标/2 速记/49 条日报）造在 IAB 独立测试档案，未碰真实库。

## 补记十一（2026-10-20 · 云端同步首配翻车）

### 3.24 "网络可达" ≠ "浏览器可调"：D1 直连的 CORS 断言翻车（3.21 同族）

- **现象**：用户按指引配好 D1 直连三项点「测试连接」→ 连不上。本机 curl 同一请求 200 正常，Token/ID 全对。
- **根因**：api.cloudflare.com **不响应 CORS 预检（OPTIONS 405）、响应无跨域头**——浏览器页面根本调不了它。设置页文案"走实测可达的 api.cloudflare.com"里的"实测"当年只测了网络可达性（curl/Node 视角），没测浏览器跨域视角。与 3.21 同族病理：断言没落到"用户实际语境"（浏览器）就下了结论；且"设备同步首验"一直挂未做，这条主路径从未被真实走过。
- **修复**：D1 查询改走本地网关代理——Node 网关与 Rust 网关双端新增 `/d1/query`（转发 api.cloudflare.com，Token 随请求带来、不落盘不记账、账户/库 ID 格式校验防注入路径）；cloudSync 网关优先、网关不在回退直连（Node 语境仍可用）。网关本就只绑 127.0.0.1、带 CORS 放行，与 AI 调用同一条已验证的通路。
- **连带边界**：手机浏览器走局域网 IP 时网关不可达（网关只绑本机），手机端 D1 拉取仍不通——设备同步的手机侧首验时再议（网关监听 0.0.0.0 或走端点模式）。
- **教训**：凡是"浏览器里的应用调外部 API"，验收必须包含 CORS 预检实测（curl -X OPTIONS 带 Origin），不能拿服务端可达当结论；文案里写"实测可达"前先问一句——在谁的语境里可达。

## 补记十二（2026-10-20 · 评分体系第一性重设计落地）

### 3.25 绝对分模型退役：三档投票 + 信源信用 + AI 画像（3.20 规则的正向应用）

- **起点**：用户问"每点一次多一颗星？"并点破本质——想要的是"和我心里的分更接近"。第一轮答复（星级×20 覆盖排序、建议浮层）被判补丁思维；用户明令"基于第一性原理出发，不要因为原来做了这个就一直延续下去"。
- **三问推演**：①假如没有现成的评分公式和 5 星：分诊只要三档（必看/可看/埋掉），人对信息的分辨力就 3 档，绝对分没有稳定语义；②"复用评分管道"只能是效率佐证——四项权重手调、星级反馈统计、调参建议这层"给公式拧参数的中间件"整体退役；③条目 ×10 后参数拟合不可维护，三档 + 自动信用天然成立。
- **落地**（2026-10-20，全绿 356 测试）：卡片三键投票（想要/一般/不要，一次点击直达、点当前档取消）替代 5 星连点；数字分徽章改"必看/可看/已埋"三档（分诊理由保留在详情）；旧 5 星读取时惰性映射（4–5→want，2–3→meh，1→no）零迁移成本；信源信用自动升降（近 60 天投票 ≥8 条：want 率 ≥60%→T1 / ≥30%→T1.5 / 其余→T2，信源页新增"想要率"列展示依据，打开应用时自动跑、变化才 toast）；AI 兴趣画像（≥20 条"想要"可归纳，之后每新增 15 条自动重跑，DeepSeek 从标题集归纳 15–30 词替换手填词表，失败保原词表静默记错）；设置页星级反馈卡与权重四项删除——零参数，校准全自动。
- **教训回收**：这是 3.20 立规后第一次完整的"推倒现成形状"实践——识别信号是用户问句里的"该怎么调整"（在旧模型内找位置）转向"有没有一种机制"（问体系本身）。**用户开始问机制而不是参数时，就该重推形状而不是加旋钮。**
- **补记（同日晚，用户点名返工）**：上段落地即翻车——"必看/可看/已埋"是换了套自造词（分诊是医疗比喻、已埋是比喻），且条目库里满屏"可看"等于没有信息；筛选标签还留着"已评分/已保留"这套分数时代内部状态名。返工：卡片徽章整个删除（分数取消了就不该留分数的影子——"三档徽章"本身就是给绝对分招魂）；筛选与状态徽章改字面词（上过日报/我标注的/已筛除）；"信源信用"并入"信源分级"词条。教训：**重设计时最危险的时刻是刚推翻旧形状之后——新造的词和旧词一样会背叛说人话；界面上每个词都要单独过"没读过文档的人一眼懂"这关，与它是不是新设计的无关。**
- **补记二（同日，第二轮返工——误读用户意图）**：用户上一轮的真实问题是"分了三类为什么只见一类"（分布诊断请求），我却听成"徽章体系该删"——把用户已认可的东西删了再被点破。真相：必看门槛 80 分，但规则引擎真实分布最高 74（325 条里 ≥80 为零）——阈值从未对过分布校准，拍脑袋定的；已筛除为 0 是该时段确实没有条目被滤掉。返工：徽章回归且改为**按同日排名分层**（每天前 2 必看/第 3–8 可看/其余可略——排名不怕分数挤在 60–70 一带，三类保证真实存在，含义=这天里先看哪条）；条目库"≥60/≥80 分"筛选（上轮漏掉的真正残留）删除，新增"必看"筛选。教训：**用户问"X 去哪了"时是在要求修 X，不是删 X；对产出的疑问先查分布再动形状。**

### 3.26 调研发现流（2026-10-21）：同一天内对同一模块的第二次第一性返工

- **链条**：用户先质疑"6 章节太麻烦"→ 瘦身到 3 节 + 一键调研 + 整篇粘贴自动拆分；当天再质疑"为什么一定要分节填写"→ 本次推倒。两次质疑都对，但第一次只修了数量、没修结构。
- **病理**：把"调研计划的结构"（该从哪些角度问）复用成了"发现的存储结构"（学到的东西必须归档进格子）。归档税不产生信息——一条材料常横跨多角度或属于计划外发现。昨天的"整篇粘贴自动拆分"本质是给错误结构打补丁：拆分逻辑整个不该存在。

### 3.27 AI 问答上下文未校准即上线（2026-10-23）：上线当天撤

- **链条**：处理页问答整段搬进 Ctrl+K（机械行为全对、真实链路实测通过）→ 用户实测问"待办"答非所问 → 对比三个开源基准（chatgpt-retrieval-plugin / Obsidian Copilot / Khoj）发现差距在"上下文只有标题没有正文"，且迁移时从未对照过任何成熟实现 → 用户拍板撤下。

### 3.28 div 扮演按钮缺交互语义（2026-10-24）：九张模板卡"点了没反应"

- **教训**：**迁入任何独立样式体系时，除作用域隔离外必须做一次令牌对齐审计**（字号/圆角/间距/颜色四级各采一遍样），否则漂移必然发生——只是早晚被用户发现。

### 3.30 回归命令跑错等价于没跑（2026-10-24）：`tsc --noEmit` 在 solution 根上零检查

- **链条**：development.md 回归清单写的是 `npx tsc -b`，但 10-23/24 多轮收尾实际跑的是 `npx tsc --noEmit` 且输出 0 错——根 tsconfig 是 solution 式（`files: []` + references），`--noEmit` 在它上面**不检查任何文件**。直到为测依赖体积跑 `npm run build`（内部 `tsc -b`）才炸出 3 个已进仓的真实类型错误（循环变量笔误 a/r、help 页相对路径错一层）。
- **病理**：检查命令与检查结果之间没有因果校验——0 错既可能来自"没错"也可能来自"没查"。测试绿给了虚假信心（vite 转译不做类型检查，类型错误不挡测试）。
- **教训**：**回归命令必须与 development.md 逐字一致，不许"等价替换"**；solution 式 tsconfig 下唯一有效命令是 `tsc -b`。已修 3 处错误并全量复跑（384 绿 / tsc -b 0 / lint 25）。

### 3.31 演示动画的载体与录制管线（2026-10-25）：GIF 截帧跳帧不流畅，浏览器录制直出 webm

- **链条**：首访引导四模块演示最初用"浏览器截帧 + Pillow 合成 GIF"（每张仅 3–6 帧），用户复检"看着不流畅"。给 GIF 加帧可行但体积近线性涨（无帧间压缩，每帧全量位图）且再多的帧也是离散跳变；改走浏览器录制接口（`tab.recording.start({ actions, fps, viewport })`，脚本动作边执行边录）直接产出 webm——8fps 连续画面，四段共 920KB，前端 `<video autoplay loop muted playsinline>` 循环播放，GIF 退役删除。
- **录制接口三个坑**：① actions 只有 wait/click/type/scroll/hover，**没有键盘事件**——N 键/Ctrl K 的演示改点顶栏速记按钮（`.quicknote-btn`）与搜索框（`.searchbox`）等效唤起；② scroll/scrollTo 动作滚不动 `.content` 这类内部滚动容器（作用于主帧）——输出模块演示改为点首屏切换控件（周期/格式切换，为此给 ReportGenerator 补了 4 个 data-testid）；③ 上一段演示结束时浮层（命令面板/速记）可能还开着，把下一段录制的全部 click 挡成 actionability 超时——**每段录制前先断言并清掉 `.overlay`**。
- **教训**：演示动画优先选"真实录屏 + video 元素"（体积小、真流畅、autoplay muted 全兼容）；截帧合成 GIF 只在目标平台不支持视频时用。录脚本动作前先设计好每个动作的**唯一定位**（strict mode 下多匹配直接失败），必要时给源码补 data-testid。

### 3.32 全项目分域深审的发现结构（2026-10-25）：六条 A 级全藏在"多步写库无守卫"与"同概念两套口径"

- **链条**：四个子代理分域（输入/处理输出/回路任务/壳系统）只读深审 + 浏览器全路由实测，共 A 级 19、B 级 43。六条最重的 A 级呈现两个共同形态：① **组合写库无守卫**——archive() 可重复执行（行动项/任务/洞察翻倍）、软删除 TTL 比较恒真（`nowIso > 过去时间` 恒成立，等于立即物理删）、一键调研在循环里读渲染闭包的旧值互相覆盖、deleteReview 不清理反向引用；② **同一概念两套口径**——分层用 UTC 日 vs 日报本地日、信源信用 60 天 vs 展示 30 天、"备份含带标注条目"的承诺 vs curatedItems 只导 scored/kept。这两种形态测试全绿时都不可见：单步各自正确，组合与口径的错位只在真实时区/长周期/重复操作下暴露。
- **子代理误报的一个样本**：audit:classes 只做正向检查（TSX 显式类名 → CSS），动态拼接类（`tier tier-${tier}`）在它的"死 CSS"清单里——删除前必须 grep 动态模板串复核。机械审计工具的结论要按它的检查原理打折。
- **教训**：组合写库路径（归档/删除/批量导入）一律事务 + 幂等守卫（`if (current.status === 'archived') return` 这一行挡住翻倍）；长循环里的追加以库为真相（读库-拼接-写回），不信组件状态；日期与统计窗口在引擎层定一个口径常量，展示侧不许自算；"承诺给用户的话"（14 天可恢复、随备份）必须有对应用例锁住，否则实现漂移无人知晓。
